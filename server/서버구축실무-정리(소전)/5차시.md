# DNS

## DNS (Domain Name System)

> 사람이 이해하기 쉬운 도메인 이름을 컴퓨터가 이해할 수 있는 IP 주소로 변환하는 시스템

### DNS 서버 종류

* **Root DNS**
  * 전 세계 DNS 서버의 최상위 서버
  * TLD 서버 정보를 제공

* **TLD DNS (Top Level Domain)**
  * 최상위 도메인 관리
  * 예: `.com`, `.org`, `.net`, `.kr`

* **Authoritative DNS**
  * 특정 도메인에 대한 실제 정보를 보유
  * 도메인의 IP 주소를 최종적으로 응답

* **Caching DNS (Recursive DNS)**
  * DNS 조회 결과를 임시 저장
  * 동일한 요청 시 빠르게 응답

---

## DNS 조회 과정

1. 사용자가 도메인 요청
2. Local DNS 서버가 Root DNS 서버 조회
3. Root DNS 서버가 TLD DNS 서버 정보 제공
4. TLD DNS 서버 조회
5. TLD DNS 서버가 Authoritative DNS 서버 정보 제공
6. Authoritative DNS 서버 조회
7. 도메인 IP 주소 반환
8. Local DNS 서버가 결과를 캐시에 저장 후 사용자에게 응답

---

## DNS Record

> 도메인과 관련된 정보(IP 주소, 메일 서버 등)를 저장하는 데이터

| 레코드 | 설명 |
|---------|---------|
| A | 도메인을 IPv4 주소로 매핑 |
| AAAA | 도메인을 IPv6 주소로 매핑 |
| CNAME | 다른 도메인의 별칭으로 매핑 |
| MX | 메일 서버 정보 제공 |
| NS | 도메인을 관리하는 네임 서버 정보 제공 |
| PTR | IP 주소를 도메인 이름으로 매핑 |

## DNS Caching

> 조회한 DNS 정보를 일정 기간 저장하여 재사용하는 기능

### 장점

* 응답 속도 향상
  * 저장된 DNS 정보를 즉시 반환

* 네트워크 트래픽 감소
  * 외부 DNS 서버 조회 횟수 감소

* 시스템 안정성 향상
  * DNS 서버 장애 시에도 일정 시간 서비스 가능

---

## TTL (Time-To-Live)

> DNS 레코드가 캐시에 저장될 수 있는 시간(초 단위)

### 특징

* 캐시 유효 기간 결정
* TTL이 만료될 때까지 기존 정보 사용
* 네트워크 트래픽 감소
* 응답 속도 향상
* 최신 정보와 캐시 효율성 사이의 균형 유지

---

## DNS 정리

* DNS는 도메인 이름을 IP 주소로 변환하는 시스템이다.
* Root → TLD → Authoritative DNS 순서로 조회가 진행된다.
* 조회 결과는 캐시에 저장되어 빠른 응답을 제공한다.
* DNS Record를 통해 IP 주소, 메일 서버 등의 정보를 관리한다.
* TTL은 DNS 캐시의 유지 시간을 결정한다.
